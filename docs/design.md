# 📐 お得速報 システム設計書

## 1. 🖥️ 画面・ユーザー操作の流れ（UI/UXフロー）
ユーザーがLINE公式アカウントを友達追加してから、セール情報を受け取るまでの動きです。

1. **友達追加（初回登録）**
   * 自動でウェルカムメッセージ（Flex Message）を送信。
   * ボタンから希望するカテゴリー（複数選択可）を選んでもらう。
2. **希望カテゴリーの保存**
   * ユーザーがボタンを押すと、その人の「LINEユーザーID」と「選んだカテゴリーID」がデータベースに保存される。
3. **カテゴリーの再編集**
   * トーク画面下部の「リッチメニュー」からいつでも設定画面を呼び出し、希望カテゴリーを追加・解除できる。
4. **セール情報の受信（セグメント配信）**
   * 管理者がお得情報を登録すると、そのカテゴリーを希望しているユーザーだけにLINE通知が届く。

## 2. 🏷️ 配信カテゴリー定義（全7種）
LINEの選択ボタン表示名と、システム内部（データベース）で管理するカテゴリーIDの対応表です。

| 表示名（LINE画面） | カテゴリーID（DB保存値） | 主な対象商品の例 |
| :--- | :--- | :--- |
| 🍚 **お米** | `rice` | 白米、無洗米、玄米、パックご飯 |
| 🥤 **飲料** | `drink` | 水、お茶、炭酸水、コーヒー、ジュース |
| 👶 **ベビー・キッズ** | `baby_kids` | おむつ、おしりふき、粉ミルク、ベビーフード |
| 🍺 **お酒** | `alcohol` | ビール、発泡酒、チューハイ、ハイボール、ワイン |
| 🧻 **日用品** | `daily` | トイレットペーパー、洗濯洗剤、柔軟剤、ティッシュ |
| 💄 **美容・コスメ** | `beauty` | シートマスク、シャンプー、スキンケア用品 |
| 🐶 **ペット用品** | `pet` | ドッグフード、キャットフード、ペットシーツ、猫砂 |

## 3. 🗄️ データベース設計（SQLite）
「100人の中から特定のカテゴリーを選んでいるユーザー」を自動で判別するためのデータ保存表（テーブル）です。

### ① ユーザー設定テーブル (`user_preferences`)
誰がどのカテゴリーを希望しているかを記録します。

| カラム名（項目） | データ型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | データの通し番号（自動増加） | `1` |
| `line_user_id` | TEXT | LINE固有のユーザー識別ID | `U1234567890abcdef...` |
| `category` | TEXT | 希望するカテゴリーID（上記定義表の値） | `rice` |
| `created_at` | DATETIME | 登録した日時 | `2026-11-12 09:30:00` |

※1人のユーザーが複数カテゴリー（例：`rice` と `daily`）を登録できるよう、複数行で保持する構造にします。

### ② 配信履歴テーブル (`deal_logs`)
管理者が手動で登録・配信したセール情報の履歴を記録します（Phase 2用）。

| カラム名（項目） | データ型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | 配信の通し番号 | `1` |
| `category` | TEXT | 対象カテゴリーID | `rice` |
| `title` | TEXT | 商品名・セール見出し | `【特売】コシヒカリ 5kg` |
| `affiliate_url` | TEXT | アフィリエイトリンク | `https://amzn.to...` |
| `sent_at` | DATETIME | 配信した日時 | `2026-11-12 12:00:00` |

---

## 4. ⚙️ システム構成・処理のイメージ
全体のデータのやり取りの流れです。

```text
[ユーザー (LINE)] 
   │  ① カテゴリー選択ボタンをタップ
   ▼
[LINE Messaging API]
   │  ② 選択データを送信 (Webhook)
   ▼
[Pythonプログラム (サーバー)] ◀── ④ 管理者：セール情報とカテゴリーを入力
   │  ③ データベースに保存 / 対象ユーザーを検索
   ▼
[SQLite データベース]
```
