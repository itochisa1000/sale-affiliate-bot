# 📐 お得速報 システム設計書

## 1. 🖥️ 画面・ユーザー操作の流れ（UI/UXフロー）
ユーザーがLINE公式アカウントを友達追加してから、セール情報を受け取るまでの動きです。

1. **友達追加（初回登録）**
   * 自動でウェルカムメッセージ（Flex Message）を送信。
   * ボタンから希望するカテゴリー（例：「お米」「飲み物」「日用品」など）を選択してもらう。
2. **希望カテゴリーの保存**
   * ユーザーがボタンを押すと、その人の「LINEユーザーID」と「選んだカテゴリー」がデータベースに保存される。
3. **カテゴリーの再編集**
   * トーク画面下部の「リッチメニュー」からいつでも設定画面を呼び出し、希望カテゴリーを変更・解除できる。
4. **セール情報の受信（セグメント配信）**
   * 管理者がお得情報を登録すると、そのカテゴリーを希望しているユーザーだけにLINE通知が届く。

---

## 2. 🗄️ データベース設計（SQLite）
「100人の中からお米を選んでいる50人」を自動で判別するためのデータ保存表（テーブル）です。

### ① ユーザー設定テーブル (`user_preferences`)
誰がどのカテゴリーを希望しているかを記録します。

| カラム名（項目） | データ型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | データの通し番号（自動増加） | `1` |
| `line_user_id` | TEXT | LINE固有のユーザー識別ID | `U1234567890abcdef...` |
| `category` | TEXT | 希望する商品カテゴリー | `rice`（お米） |
| `created_at` | DATETIME | 登録した日時 | `2026-11-12 09:30:00` |

※複数カテゴリー（お米と飲み物の両方など）を選べるように、1人のユーザーに対して複数行保存できる構造にします。

### ② 配信履歴テーブル (`deal_logs`)
管理者が手動で登録・配信したセール情報の履歴を記録します（Phase 2用）。

| カラム名（項目） | データ型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | 配信の通し番号 | `1` |
| `category` | TEXT | 対象カテゴリー | `rice` |
| `title` | TEXT | 商品名・セール見出し | `【特売】コシヒカリ 5kg` |
| `affiliate_url` | TEXT | アフィリエイトリンク | `https://amzn.to...` |
| `sent_at` | DATETIME | 配信した日時 | `2026-11-12 12:00:00` |

---

## 3. ⚙️ システム構成・処理のイメージ
全体のデータのやり取りの流れです。

```text
[ユーザー (LINE)] 
   │  ① カテゴリー選択ボタンをタップ
   ▼
[LINE Messaging API]
   │  ② 選択データを送信 (Webhook)
   ▼
[Pythonプログラム (サーバー)] ◀── ④ 管理者：セール情報とカテゴリーを入力
   │  ③ データベースに保存 / 対象ユーザーを検索
   ▼
[SQLite データベース]
```
