# 🗓️ LINEアフィリエイト（お得速報）開発計画書

## 1. 📌 プロジェクト基本方針
* **システム名**: お得速報（LINEセグメント配信システム）
* **開発・リリース方針**: **段階的リリース（フェーズ別公開）**
  * すべての機能を一度に作るのではなく、Phase 1〜3の各段階で「動くもの」を順次リリースし、実際のユーザー反応や運用データを確認しながら機能と収益モデルを成長させます。
* **開発体制**: 個人開発（設計・実装・リリース・運用）

---

## 2. 🚀 段階的リリース計画（フェーズ別ゴールと完了基準）

各フェーズの終了時にリリースを行い、次のフェーズへ移行します。

### 【Phase 1 リリース】ユーザー登録基盤の公開（Ver 0.5：先行登録スタート）
セール配信機能を作る前に、まずは「自分の欲しいカテゴリーを登録できるLINE公式アカウント」として公開し、初期フォロワー（見込み客）を集め始める段階です。

* **Step 1-1：開発環境と外部APIの連携**
  * [x] LINE公式アカウントの開設 ＆ Messaging APIの有効化
  * [ ] Eclipse (PyDev) のセットアップと GitHub リポジトリとの連携
  * [ ] PythonからLINEへテストメッセージを送信する疎通確認
* **Step 1-2：データベース基盤の構築**
  * [ ] SQLiteデータベースの作成（`user_preferences` テーブルの実装）
  * [ ] データの登録・検索・削除を行うPythonモジュールの作成
* **Step 1-3：ユーザー登録画面の実装**
  * [ ] 友達追加時のウェルカムメッセージ（7カテゴリー選択用 Flex Message）の作成
  * [ ] ボタンタップ時にユーザーのLINE IDとカテゴリーをDBへ自動保存する処理（Webhook）の実装
  * [ ] リッチメニューからのカテゴリー再編集・解除機能の実装
* **🏁 Phase 1 リリース完了基準**:
  * SNS（Instagram / X）から友だち追加したユーザーが、7つのカテゴリーから自分の好みをエラーなく登録・変更できる状態になっていること。

---

### 【Phase 2 リリース】手動セグメント配信の公開（Ver 1.0：正式サービス開始）
集まった登録ユーザーに対して、管理者が手動でピックアップしたお得情報を「カテゴリー別に出し分け配信」し、アフィリエイト収益化をスタートさせる段階です。

* **Step 2-1：管理者向け配信ツールの作成**
  * [ ] セール情報（対象カテゴリー、商品名、アフィリエイトURL）を入力する管理画面またはコマンドツールの作成
  * [ ] 配信履歴（`deal_logs` テーブル）への自動記録処理の実装
* **Step 2-2：セグメント配信ロジックの実装**
  * [ ] 指定されたカテゴリーを希望しているユーザーIDのみをDBから抽出する処理
  * [ ] 抽出したユーザー全員に対して一斉プッシュ通知を送る処理
* **🏁 Phase 2 リリース完了基準**:
  * 管理者が「お米」のセール情報を登録した際、「お米」を選択しているユーザーにのみPR表記付きの通知が届き、それ以外のユーザーには届かないこと。
  * 実際のユーザーへの配信を通じ、リンククリックおよびアフィリエイト成果が発生すること。

---

### 【Phase 3 リリース】自動化・機能拡張版の公開（Ver 2.0：スケールアップ）
Phase 2の運用で「どのカテゴリーがよく売れるか」のデータと収益が確立した段階で、手作業での情報収集・配信を自動化し、システムを拡張する段階です。

* **Step 3-1：情報収集の半自動化**
  * [ ] Amazon PA-API や 楽天ウェブサービスAPI を用いた商品データ・価格情報の自動取得
* **Step 3-2：配信の自動化と分析**
  * [ ] 設定した割引率（例：30%OFF以上など）を下回った際の自動通知バッチ処理
  * [ ] カテゴリー別の登録者数やリンククリック率の集計機能
* **🏁 Phase 3 リリース完了基準**:
  * 管理者が毎日手動で商品を探さなくても、システムが自動でお得商品を検知し、対象カテゴリーのユーザーへ自動配信・収益化できるサイクルが稼働していること。

## 3. ⚠️ リスクと対策（トラブル防止策）

| 想定されるリスク | 対策・回避ルール |
| :--- | :--- |
| **LINEの無料メッセージ通数制限** | LINE公式アカウントの無料プランは月間の配信数に上限（200通など）があるため、セグメント配信（出し分け）を徹底して無駄な送信を完全に防ぐ。 |
| **アフィリエイト規約違反** | Amazonアソシエイトや楽天アフィリエイトの規約を確認し、URLの短縮ルールやステマ規制対応（「PR」「広告」表記の明記）をメッセージテンプレートに必ず組み込む。 |
| **セキュリティ情報（APIキー）の漏洩** | LINEのアクセストークンやシークレットキーはコードに直接書かず、必ず環境変数（`.env`ファイル）で管理し、GitHubにはアップロードしない（`.gitignore` に登録する）。 |
